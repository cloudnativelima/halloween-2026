Los permisos de los RoleBindings se acumulan. El acceso al Secret de soporte se
concede a un grupo de ServiceAccounts y otros bindings amplían el acceso de
`audit-agent`. Además, el Pod recibe copias del Secret. Vamos a asignar la
identidad correcta a cada Deployment y quitar esas copias del Pod de auditoría.

```text
$ kubectl -n possessed-sa edit deployment audit-agent
deployment.apps/audit-agent edited
```

Configura `serviceAccountName: audit-agent` y conserva el montaje de su token.
Quita `ARCHIVED_SUPPORT_PAYLOAD`, el initContainer `support-archivist`, su
`emptyDir`, el volumen proyectado del Secret y los `volumeMounts` asociados.

```text
$ kubectl -n possessed-sa edit deployment support-agent
deployment.apps/support-agent edited
```

Configura `serviceAccountName: support-agent` y habilita el montaje de su token:

```yaml
automountServiceAccountToken: true
```

```text
$ kubectl -n possessed-sa edit configmap audit-ledger
configmap/audit-ledger edited
```

Conserva `record: audit-only` y quita `support_archival_note`.

```text
$ kubectl -n possessed-sa edit rolebinding support-secret-reader
rolebinding.rbac.authorization.k8s.io/support-secret-reader edited
```

Asocia este RoleBinding únicamente a la ServiceAccount `support-agent`:

```yaml
subjects:
  - kind: ServiceAccount
    name: support-agent
    namespace: possessed-sa
```

Los otros bindings no deben conceder acceso a `audit-agent`. Deja `subjects: []`
en `legacy-telemetry`, `forgotten-support-delegation` y
`support-emergency-access`. Conserva `audit-ledger-reader` y los Roles de
lectura nombrada que usan las aplicaciones.

```text
$ kubectl -n possessed-sa edit rolebinding legacy-telemetry
rolebinding.rbac.authorization.k8s.io/legacy-telemetry edited

$ kubectl -n possessed-sa edit rolebinding forgotten-support-delegation
rolebinding.rbac.authorization.k8s.io/forgotten-support-delegation edited

$ kubectl -n possessed-sa edit rolebinding support-emergency-access
rolebinding.rbac.authorization.k8s.io/support-emergency-access edited

$ kubectl -n possessed-sa rollout status deployment/audit-agent
deployment "audit-agent" successfully rolled out

$ kubectl -n possessed-sa rollout status deployment/support-agent
deployment "support-agent" successfully rolled out

$ kubectl -n possessed-sa logs deployment/possession-observer | grep 'verification completed'
exorcise: ... possession-auditor verification completed
```

`audit-agent` puede leer solo `audit-ledger` y recibe Forbidden al consultar los
demás ConfigMaps y Secrets. El Service de soporte sigue funcionando.
